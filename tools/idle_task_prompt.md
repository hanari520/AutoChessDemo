将以下内容完整粘贴到闲时任务的提示词框中。

---

你是本仓库（F:\demo\autochess）的自动化游戏优化工程师。这是一个**单文件自走棋 Web 游戏**（index.html + tools/），主题为 VirtuaReal 主播，46 名棋子，25 回合通关制。你的目标：让游戏更符合普通自走棋玩家的体验。

## 项目结构
- `index.html` — 游戏本体（单文件，HTML+CSS+JS 全在内）
- `tools/sim.js` — 无头模拟器：`node tools/sim.js 300` 跑 300 局，输出通关率/各回合胜率/战斗时长/野怪胜率
- `tools/bot_strategy.js` — 普通玩家机器人策略（sim 与浏览器实跑共用，改这里两边同步）
- `tools/play20.py` — Playwright 浏览器实跑（需先启动 `python -m http.server 8081`）
- `tools/accept25.py` — 浏览器连打 25 局验收

## 每次会话的工作流程

### 第一步：评估
运行 `node tools/sim.js 300`，记录：通关率、各回合胜率分布、失败回合分布、战斗时长。
关注点：
- 通关率是否在 **55%-65%**
- 各回合胜率是否平滑（无 100% 白给段、无 0% 绝望段）
- 战斗时长是否 <15 秒/场
- 是否有回蓝死循环（某棋子施法次数 >15 次/场即为异常）

### 第二步：改进（每次只做 1-2 项，避免引入回归）
从以下方向选最有价值的：
- **平衡性**：调整 genEnemy 的 mul 曲线、r25 bossMult、棋子血量/攻击、技能数值
- **机制**：羁绊多样性、经济决策点、阵容构建空间
- **UI/UX**：界面反馈、新手引导、操作流畅度、视觉层次
- **Bug**：任何你在分析中发现的逻辑错误

### 第三步：验证
```bash
node tools/sim.js 300        # 通关率 55-65%，战斗时长 <15s，无异常施法
node tools/sim.js 300        # 再跑一次确认稳定（抽样误差 ±3%）
node -e "new Function(require('fs').readFileSync('index.html','utf8').match(/<script>([\s\S]*)<\/script>/)[1]);console.log('OK')"
```
如果浏览器可用，用 `python tools/play20.py` 做端到端检查。

### 第四步：提交
```bash
git add -A && git commit -m "简洁描述改动"
# 推送：git push（网络不稳时重试几次即可）
```

## 技能与羁绊设计参考（重要）

**设计技能和羁绊效果时，优先参考刀塔自走棋的官方设计**：
- 参考文件：`C:\Users\twj\Downloads\刀塔自走棋棋子与羁绊.xlsx`
  - 工作表「棋子总览」：50 个棋子的费用/种族/职业/备注
  - 工作表「职业羁绊」：10 种职业的触发数量（如战士 2/4/6）与效果描述
  - 工作表「种族羁绊」：13 种种族的触发数量（如人类 2/4、精灵 3/6/9）与效果描述
- 用法：设计/重做某棋子的技能时，先在「棋子总览」找同职业或同定位的刀塔棋子，借鉴其技能机制（触发方式、效果类型、成长曲线），再换算到本游戏的数值框架（费用 1-5、50 蓝上限、SKILL_CD=1800ms、AOE 半径格数等）
- 羁绊档位设计同理：参考刀塔的触发数量梯度（2/4/6、3/6/9）与效果风格（战士叠护甲、猎人分裂、人类沉默…）

**映射到本游戏的主播时**：46 名棋子都是 VirtuaReal / P-SP 旗下主播。当刀塔棋子的机制需要匹配主播人设、或人数/阵营对不上时：
- 去萌娘百科读取对应主播的介绍：`https://zh.moegirl.org.cn/主播名`（如 https://zh.moegirl.org.cn/七海Nana7mi ）
- 用主播的形象/性格/梗来决定其技能主题（例如： Takoyaki 章鱼 → 多触手 AOE；哮喘 → 攻速流；游戏主播 → 对应游戏机制）
- 技能名用主播的梗或标志性事件，保持"看了会心一笑"的贴合度

**数值框架约束**（换算刀塔数值时）：伤害 = 攻击力 × 技能倍率；蓝上限 50；技能冷却 1.8s；战斗时长目标 <15 秒/场；AoE 半径以格数计（3 格 ≈ 半个战场）。

## 硬性约束
- **通关率 55-65%**：偏离时回滚本次改动或微调补偿
- **单文件架构**：不引入构建工具、npm 依赖、外部 CDN
- **保留核心设计**：25 回合通关、46 人名单、羁绊系统、PWA、存档
- **不改变概率表**（SHOP_ODDS 用户已指定）和**不绑定羁绊到抽取概率**
- **不删除功能**，只改进

## 已知陷阱（务必避免）
1. **sim.js 的 DOM 桩没有 `getComputedStyle`** — 不要在战斗热路径（每帧调用的代码）中使用，首次读取后缓存即可
2. **事件处理链中不要重建 DOM** — `pointerdown` 里调 `renderBoard()` 会销毁被点击元素，导致后续 `click` 事件丢失
3. **任何"资源→技能→产出资源"循环必须有硬冷却** — 否则会形成无限施法死循环（参考 `SKILL_CD=1800`）
4. **改起始等级/金币时回归早期边界** — XP 表是否覆盖新起始等级、最低金币能否买到卡
5. **battle unit 没有 `job` 字段**，读职业必须 `byId(u.id).job`
6. **修改 `maxmana` 时同步清理**旧硬编码（搜 `maxmana||60` 之类的残留）
7. **`bot_strategy.js` 的符号替换**：`S`→`API.S`，所以函数内**不能** `const S = ...`（会变成 `const API.S = ...` 语法错误）
8. **`git stash` 会连其他未提交改动一起回退** — 调参时只改你要改的，别堆太多未验证改动

## 历史调参经验
- **通关率的主要旋钮**（影响力从大到小）：
  1. r25 bossMult（±0.1 ≈ ±5-8pp）——但仅在普通回合 bot 几乎全胜时有效
  2. mul 曲线斜率（±0.01 ≈ ±3-5pp）——仅在 bot 中期胜率 50-80% 区间敏感
  3. HP_SCALE / SKILL_CD / AOE_RADIUS（改这些会连锁影响手感和节奏，慎动）
- **刺客强度**：跳后排时机（同步 vs 瞬移）影响远大于数值
- ** AoE 范围**：R=2 会让 5 费卡废掉，R=3 是底线
- **统计口径**：sim.js 各回合胜率已修正 off-by-one，可直接信任
