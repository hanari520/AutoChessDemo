# 八人联机接入 Adaptive v4.3 · 2026-10-01

## 实现

经典托管与八人房间机器人调用同一份 `tools/bot-planner.js`。原经典 `bot_strategy.js` 成为游戏动作适配层，服务器 `bot-adapter.js` 将公开的备战数据映射为决策输入，通过原有 `applyAction` 执行买卖、经验、刷新、布阵、锁店和装备操作。房间已有 `runBots()` 入口直接运行新策略，每次进入备战都会更新。

联机端遵守八格备战席、人口上限和共享卡池；满席购买不会使用经典的临时合成槽。择优换人通过合法交换执行，不丢弃棋子。对手情报来自 `viewFor().players[].board` 的上回合锁定快照，按快照格子映射站位，不读取对方当前棋盘、备战席、商店、余额或私有随机流。阵容方向和策略版本以可序列化字段保存在机器人座位，正常客户端视图不暴露这些字段。

共享策略由 `server-online/scripts/sync-runtime.mjs` 复制到服务器部署包，`online/runtime-sync.test.js` 验证副本一致。页面加载顺序为装备策略、决策引擎、经典适配层，Service Worker 缓存更新为 v120。

## 验证

- 经典种子 12001–12010：抽取前后逐局完整结果 JSON 完全相同；默认模拟作用域和浏览器实际词法作用域分别验证，共 40 次完整模拟。
- 经典机器人契约：16 项通过，包含托管 UI 根据函数参数个数等待搜牌完成的异步契约。
- 联机专项：10 项通过；包含公开情报隔离、满席替换、满席购买、锁店后付费刷新、准备锁定和装备守恒。第 11 项完整八机器人及持久化测试遇到下面记录的原有战斗崩溃。
- 服务器测试：56 项中 55 项通过，唯一失败为上述毒装备战斗崩溃。房间启动和下一轮备战运行全部七个机器人，已在房间 prelock 测试中验证。
- 联机规则/备战/经典一致性/源码同步测试：28 项通过。
- 独立只读复审：未发现新增机器人缺陷；已将开局选择及首次部署纳入 `try/finally` 的自动就绪保障。

## 待处理的战斗崩溃

`online/combat.js:538` 的 `onAttack()` 在毒羽连弩触发时引用未定义的 `k.bleedDuration`。此错误存在于接入前的战斗源码，本次未改动战斗引擎。经典相同装备逻辑在 `index.html` 使用 3000 毫秒中毒时间；毒装备伤害系数为既有 .012。

20 个八机器人种子中 12 局正常结束，8 局均因 `k is not defined` 中断。250 个备战窗口中共享卡池、人口、装备槽及就绪检查均通过；整桌决策平均 8.29 毫秒，观测最大 24.76 毫秒，仅代表本机测试性能。失败种子及轮次均保留在原始 JSON。

用户此前限定“只能修改托管机器人的运行逻辑”。单点修复战斗变量需要额外授权，已提出异步确认；授权到来前保留该错误，不禁用装备、不绕开触发种子。完整验收暂未通过，未部署。
