# 对局入口与生命周期重设计计划

本文件为待实施设计，不代表功能已经实现。本轮仅审查源码和用户截图，不修改游戏代码。

## 已确认的问题

- index.html 的 closeIntro 在首次进入时会通过 ×/Esc 调用 startSelected；关闭与开始语义混淆。
- showIntro、章节结算、终局共用 overlay/ovText/ovBtn，动态修改 onclick；showIntro 未统一恢复按钮处理器，存在残留动作风险。
- resetBtn 打开模式选择，没有保留 arena 默认模式；restartGame 只传 daily/arena，丢失自定义诅咒配置。
- initApp 按每日→竞技→普通选一个续玩档，忽略保存时间，也隐藏其他有效档。
- ovResume 不检查 loadGame 返回值就关闭菜单并显示恢复成功；读取失败可能继续操作预览状态。
- startSelected/startDaily/restartGame 等路径存在跨模式删除竞技存档的行为。
- 结束挑战以三秒内再次点击确认，后果主要写在日志中，缺少稳定、明确的确认界面。
- 截图中首页同时承担模式设置、说明和续玩，两个渐变主按钮竞争；有横向滚动条。

## 页面与动作

### 1. 主菜单

作为完整页面，不显示关闭 ×，Esc 不创建对局。保留现有角色美术和主题。

有有效存档：主区展示最近存档卡片，包含模式、回合、生命、保存时间及每日日期，主按钮“继续对局”；次按钮“新建对局”。多个有效档显示“其他存档”，可直接选取，不按固定模式优先级隐藏。

无存档：主按钮“新建对局”，不展示续玩按钮。玩法说明、战绩是次级入口。第一页不展开模式配置和长篇教程。

### 2. 新建对局

独立设置页：普通、八人竞技、每日挑战、自定义诅咒四种模式，明确目标与规则。选择只更新草稿，不改当前局、随机数或存档。

底部主按钮“开始普通模式”等，次按钮“返回”。自定义只在该模式展示诅咒；每日展示日期、种子和规则。若将覆盖目标槽存档，最终开始前确认，列出被覆盖档；取消保留原档和草稿。不得删除其他槽。

### 3. 局内菜单

顶栏保留“玩法说明”，把重开和结束收进“对局菜单”，危险项用红色文字而非主按钮。

| 动作 | 确定语义 |
| --- | --- |
| 返回对局 | 关闭菜单，恢复当前页面 |
| 保存并返回主菜单 | 保存当前可恢复状态，不结算，不丢进度 |
| 重新开始本局 | 确认后放弃本局，沿用模式和规则，从第1回合开始 |
| 结束本局并结算 | 确认后提前结束，记录战绩，删除本局续玩档，进入结算 |

“重新开始本局”确认文案：“将放弃当前第 N 回合进度，按相同模式和规则从第 1 回合开始。此操作不记录本局战绩。”按钮“取消 / 放弃进度并重开”。普通和竞技生成新局随机状态；每日沿用当日种子；自定义完整保留诅咒。每日跨天不冒充同配置重开，解释后进入今日挑战设置。

“结束本局并结算”确认文案：“将结算当前成绩，结束后无法继续此局。”按钮“继续对局 / 结束并结算”。竞技明确提前退出将按现有淘汰规则计算名次。沿用现有排行资格：提前收兵不应被此重构擅自取消排行资格。

### 4. 玩法说明

独立只读面板：快速上手（购买→上阵→开战→备战）、经济与升星、羁绊与装备、当前模式规则、操作方式。数值以源码为准。

来自首页关闭回首页，来自局内关闭回原对局，来自结算关闭回结算。按钮统一“关闭说明”，绝不开始、重开或加载存档。不得复用战报内容节点。

### 5. 结算

分别表达胜利、失败、提前结束和竞技名次。保留战报、战绩与现有排行提交功能，主按钮“再来一局”，次按钮“返回主菜单”。“再来一局”沿用最终对局配置，不读取之前在设置页选择的草稿；日期变化按上述每日规则处理。

章节奖励是对局中间状态，不是终局；选择奖励、继续下一章与终局按钮隔离。

## 状态和存档约束

1. UI 页面状态与游戏状态分离：home/setup/game/help/confirm/result 是界面；prep/battle/chapter/over 是对局阶段。help/confirm 保存来源。按钮调用明确动作，不通过按钮文字或全局 ovMode 猜测行为。
2. 确认层 ×、Esc、点遮罩均只取消；设置页返回也不创建游戏。对话框隔离游戏快捷键，恢复焦点。
3. 备战打开菜单/说明/确认层后暂停托管和自动开战调度；取消后按原意图恢复，不出现多个调度。战斗中说明只读，本场战斗继续，阻止自动进入下一战；重开、保存返回、结束暂禁用并说明“本场战斗结束后可操作”。战斗转备战时更新菜单可用状态。
4. 章节选择阶段可查看说明；先完成奖励选择再允许保存返回/重开/主动结束，避免静默丢奖励。明确提示。刷新恢复旧备战检查点的现有限制需如实告知。
5. 本期保留现有三个槽：普通与自定义共享 vc_save4，每日 vc_daily3，竞技 vc_arena3。UI 明示普通与自定义共用存档位，覆盖只影响目标槽。此选择控制迁移成本，不扩展为无限存档系统。
6. 存档加入 schemaVersion、runId、mode、runConfig、savedAt、可恢复阶段等必要元数据；兼容现有 ts 字段。旧普通/自定义根据 curses 推断，无法分辨的空诅咒旧档按普通兼容，不伪称能恢复原始模式。
7. 每个槽独立解析校验，一个坏档不阻断其余档。先验证再提交恢复状态，失败留在菜单，明确原因，不显示成功、不调用 renderAll 覆盖原档。加载后默认暂停自动操作，提供明确启用入口。
8. 每日日期/规则失效档说明不可继续，不静默删除；用户明确开始替换或清除时再处理。浏览器保存失败时不得提示“已保存”，保存返回失败应留在对局。
9. 终局处理以 runId 幂等：战绩只写一次、清理调度一次、只删除所属槽。快速双击不得重复开局或结算。历史与成就不随重开清空。
10. 跨局的异步战斗、托管、自动开战回调检查会话标识，禁止旧回调写入新局。

## 实施顺序

1. 盘点启动、帮助、模式设置、章节、结束、重开、恢复、终局路径及 UI 装饰钩子；建立回归用例。
2. 先拆分页面状态、明确动作入口和存档查询/验证/恢复职责，修正关闭即开局、读档假成功和跨槽误删。
3. 实现主菜单、新建页、只读说明和统一对局菜单；接入两类确认与配置保持。
4. 接入终局幂等、计时器保护、每日失效说明和旧档兼容。
5. 验证桌面、窄屏与横屏，回归原有战斗及章节路径，提供变更说明与截图。

## 验收清单

- 首次进入和连续 Esc 不产生对局、存档、战绩或自动战斗。
- 有三个档时按时间推荐，其他档可见；继续不受新局模式选择影响。
- 帮助多次开关，包括章节和结算后查看，均不改对局数据、模式或按钮动作。
- 设置中切换模式后取消，当前局及各存档保持一致。
- 覆盖同槽需明确确认；普通/每日/竞技互不误删；普通与自定义共享槽有提示。
- 四种模式重开/再来一局均正确保持配置，自定义不退化为普通，竞技不跳普通。
- 结束取消可继续；确认只写一次战绩且不可续玩；仍保留应有排行提交入口。
- 损坏存档、旧档、过期每日、保存失败均有可理解反馈，不报假成功、不破坏原数据。
- 托管、自动开战开启时打开/关闭菜单与确认层、战斗结束、快速双击、刷新均无重复执行或旧回调污染。
- 章节奖励、通关、失败、竞技结算不串页、不重复发奖。
- 1366×768、390×844、740×360 下无横向滚动，长内容只在一个区域纵向滚动，主操作可达；支持键盘焦点和触屏。
