# 可直接交给执行 Agent 的提示词

请在 F:\demo\autochess 实现对局流程重构。先读取项目适用的 AGENTS.md，再完整读取 specs/general/GAME-FLOW-REDESIGN.md，把它作为本次实现和验收规格。需要实际完成代码和验证，不要只回复建议。

背景：当前首页、玩法说明、重开、续玩、章节与结算复用 overlay/ovText/ovBtn，造成关闭即开局、按钮处理器残留、续玩对象不清晰、重开模式丢失与存档误删风险。本任务统一对局生命周期，不调整战斗数值或各模式玩法。

实施要求：
1. 先检查现状，尊重未提交改动；目标是 autochess/index.html 及其实际加载的 tools/idol-* 界面文件，不要误改 autochess-redesign/archive。规格中的函数名和行号仅作定位线索，以当前代码为准。
2. 拆分主菜单、新建设置、只读玩法、确认层、章节界面和最终结算。明确界面状态与对局阶段；共享视觉外壳可以，但不得复用可变内容和遗留 onclick 来决定动作。删除或归并旧 resumeOv、ovBtn3 等冗余入口及其可触发事件，兼容现有移动端更多抽屉。
3. 主菜单按有效存档保存时间推荐，其他档可选择；无档不显示继续。设置只改草稿；开始才创建对局。同槽覆盖确认，禁止跨模式误删。保留三个旧槽及兼容读取，明确普通/自定义共享槽。
4. “重新开始本局”固定沿用本局配置并确认放弃，不记录此次弃局战绩；“结束本局并结算”确认后记录提前结束并使该局不可续玩。结果页提供再来一局/返回主菜单。保留提前结束的既有排行榜资格和竞技名次规则。
5. 帮助的关闭、确认的取消、设置的返回都不能开新局。实现规格中的战斗/章节阶段限制、自动调度暂停恢复、会话标识和终局幂等。不要为本任务强造完整战斗暂停系统。
6. 修复 loadGame 失败却提示成功；独立校验每个槽，恢复先验证后提交，恢复失败不覆盖旧档。加入必要元数据并兼容旧档。存储失败不可宣称保存成功；过期每日清楚解释，不静默删除。
7. 更新 idol-ui-redesign.js 等装饰逻辑，使教程与战报不再搬动同一节点。沿用角色资源和整体风格，首页收敛主按钮；无横向滚动和嵌套滚动陷阱。补齐可访问名称、焦点管理和弹窗快捷键隔离。
8. 使用已有测试/模拟器并添加必要的生命周期回归测试，重点断言存档、战绩次数、对局配置、计时器与取消前后数据。依据规格完整验收四种模式、读档异常、跨天每日、章节/终局、托管/自动开战及快速重复操作。至少检查 1366×768、390×844、740×360，并保存关键页面截图。不要把未实际运行的检查写为通过。
9. 若项目使用 Service Worker，检查资源缓存是否妨碍新界面生效，按现有方式更新所需版本。不要部署、发布、推送，不安装无关依赖，不改战斗平衡、排行协议或历史成绩。

最终交付：简要说明最终交互流程、修改文件、测试命令与实际结果、界面截图路径、旧档兼容行为及任何未完成项。如果规格与真实引擎边界冲突，先采取最小安全实现并明确说明，不静默更改产品语义。
