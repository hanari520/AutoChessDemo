# G1《今晚谁来播》计划书

## 定位与体验

单人模拟经营，首版本地运行，支持暂停续档。玩家经营一个架空虚拟主播社团，用四周时间准备首次联合演出。重点体验是“我安排的组合产生了不同节目效果”，而非等计时器收钱。

目标单局 25–40 分钟。六名角色可选择三名作为初始成员，角色通过偏好与能力分布形成差异；不给真实主播作现实能力排名。

## 首版规则草案

- 战役四周，每周三档节目，按档结算，无现实时间等待。
- 初始资金 100、社团热度 0、各成员精力 80/100。第一档前有可跳过的引导。
- 每档安排一个节目、最多两名成员；未出场成员恢复 15 精力。休息档不获节目收入、全员恢复 25。
- 五类节目：游戏、杂谈、歌回、教学、双人联动；节目定义基础成本、收益、精力消耗和匹配特征。
- 节目质量 Q 初始采用 0–100 有界公式：基础 40＋特长匹配 0/10/20＋设备加成 0/5/10＋组合加成 0/10－疲劳惩罚 0/15＋事件修正。投入成本、精力变化和预计 Q 区间在确认前显示。
- 节目基础收入、成本与热度增量全部配置化。用 Q 的分档系数结算，不在 UI 藏额外随机修正；事件随机由战役种子决定。
- 首版 12 个事件，每档至多一个，每个两个选项，明确即时成本，允许少量有提示的延后影响。同一战役事件无放回抽取，耗尽后安全跳过。
- 资金不足以开节目时可以免费休息或低成本杂谈，不允许进入无法点击任何动作的状态。
- 第四周结束进入联合演出：从已有节目中选三项，按准备、成员状态和节目多样性结算三个评价结局。所有结局可完成游戏；阈值通过模拟与试玩调节，首版不设突然破产删档。

数值均为起始实验值，G1-01 验证后冻结 rulesVersion。目标是至少“专精节目”和“均衡轮换”两种策略能完成战役，不能证明时先调机制再加内容。

## 页面与保存

新建/继续 → 周计划（档期、成员状态、现金）→ 节目预览 → 事件选择 → 单档结算 → 周总结 → 联合演出 → 战役总结。桌面三栏，手机分为档期/成员/设备页签，确认操作保持可见。

在节目确认前、事件选择后、结算后保存。事件发生后读档不能换事件；相同 actionId 不重复扣款。离开事件页回来仍显示未选择事件。结算展示实际变化与原因。

## MVP 与后续

MVP：6 角色、5 节目、3 类设备各 2 次升级、12 事件、1 场终演、3 评价结局、3 类纪念物。主要使用现有立绘和图标，占位舞台先验证。

后续：角色个人企划、更多社团风格、工作室装饰、分支巡演。首版不做现实时间挂机、员工雇佣市场、付费抽卡、多人经营或所有 50 人的专属剧情。

## 技术与任务

拥有目录 `games/studio-manager/`。规则核以 arrange/show/event/upgrade/rest/finale 动作驱动；数据文件保存节目、成员特征和事件，禁止在 UI 中计算经济。

任务 G1-01 至 G1-04：规则与单档闭环 → 四周完整战役 → 存档恢复与共享奖励 → 内容表现与试玩。详细验收见 [任务清单](tasks/todo.md)。

## 验收场景

- 低资金、零精力、全部休息、相同节目连播均能走到明确结尾，不出现负资金购买或无动作软锁。
- 固定种子与动作序列得到相同结算；事件选择重复提交、刷新后不重复扣款。
- 三种预设策略跑完整战役，输出每档资金/精力/Q；至少两种合理策略能达成中档以上结局，阈值和证据随版本记录。
- 新玩家能在第一档结算后解释“这档为什么表现好/差”。真人验证未进行时保留待验收标记。

## 风险与决策

若只有最高收益节目值得选择，优先调整疲劳、节目组合和观众偏好，而不是增加更多同质节目。若排班变成繁琐填表，允许复用上周方案并显示风险，不自动替玩家做核心决策。
