# 交给其他 agent 的执行说明

## 先读

1. 项目适用的 AGENTS.md。
2. 本目录 README.md、tasks/plan.md、00-platform.md。
3. 所选游戏计划与 tasks/todo.md 中对应任务。
4. 09-ai-art-policy.md：用户已允许所有项目 AI 重新生成美术，不必重复询问是否可以生图。

这些文档定义拟实施范围，不代表功能已经存在，也不意味着一次要实现八款游戏。不要自动执行旧 `autochess/tasks/` 的八人联机计划。实际代码与本文现状描述不一致时，先记录证据并修订该任务假设。

## 通用执行提示词

把下面模板中的任务 ID 换成要执行的任务，即可交给 agent：

> 请在 F:/demo/autochess 执行 specs/game-library/tasks/todo.md 中的【任务 ID】。
> 先阅读适用 AGENTS.md、specs/game-library/tasks/plan.md、00-platform.md 和对应游戏计划。
> 本次只负责该任务列出的目录和验收范围。你不是代码库里唯一的工作者，不要撤销其他人的改动；发现共享文件冲突时协调负责人，兼容已经发生的修改。
> 先检查依赖是否已交付；依赖缺失但可使用明确标记的本地适配器完成独立规则工作时继续该部分，不能伪造联网或云存档已完成。
> 保持现有游戏入口与存档兼容。新玩法用独立目录、规则核和数据配置，不把所有代码塞进旧 index.html。
> 实现最小完整纵向切片，完成有意义的规则测试与真实浏览器验证。产出实际命令、结果、截图或日志，以及未验证项。
> 可使用 AI 重新生成该游戏的美术资产，不要求沿用旧立绘。先做游戏内视觉样本，通过一致性、清晰度与加载检查后扩量；保留来源和版本清单，遵循 09-ai-art-policy.md。
> 大于一次聚焦会话的任务先细分，不能省略验收条件。只勾选真正完成的任务。本次不自动部署、不创建付费资源。

## 单人作品的首次派发建议

尚未选具体作品时，从下面三条中选一条即可，互不要求先做社交系统。

- 经营：执行 G1-01，参照 01-studio-manager.md，实现单档排期、事件和结算。范围限 games/studio-manager/，暂用内存存档。
- 卡牌：执行 G5-01，参照 05-danmaku-deck.md，实现完整单场卡牌战斗。范围限 games/danmaku-deck/，先用占位视觉。
- 剧情：执行 G2-01，参照 02-midnight-store.md，实现首夜和一次顾客回访。范围限 games/midnight-store/，先验证分支有意义。
- 格斗：执行 G8-01，参照 08-star-fighters.md，先用木桩实现固定步进、攻防判定与训练；范围限 games/star-fighters/。首版单人对 AI，不需要先做联网。

需要共享清单与恢复进度时，另派 P01/P02/P04，不让游戏 agent 顺手各写一套冲突的公共模块。单人首版不要求用户注册、不等待联机后端上线。

## 多 agent 分工建议

| 责任 | 拥有范围 | 避免触碰 |
|---|---|---|
| 平台负责人 | library/、公共服务合同、共享存档 | 各游戏规则与内容 |
| 某游戏负责人 | games/<指定游戏>/，必要时该游戏服务端子目录 | 别的游戏、共享房间生命周期 |
| 联网负责人 | services/game-library/ 的公共房间/身份模块 | 旧八人房间服务，除非另有明确任务 |
| 集成负责人 | 新游戏注册、首页链接、缓存与部署排除配置 | 重写各游戏核心 |
| 审查负责人 | 只读检查及问题报告 | 未协调就代替负责人改文件 |

可并行：G1-01、G2-01、G5-01 等独立游戏规则；平台合同冻结后的各客户端集成。

必须顺序：共享合同→共享实现；P07→P08→多人对接；单案事实图→故事扩写；音频时钟→谱面扩充；数据迁移→云同步接入。

项目只允许 Luna/Sol，Sol 不超过 medium；researcher 处理清点，coder 处理常规实现，expert 处理架构/联网/时序/迁移，reviewer 处理独立复核。依照项目失败升级规则，报告已收集证据，不重复无效尝试。此分工表供未来派发使用，本轮没有启动实现 agent。

## 不应自行扩大范围的事项

不默认增加每日签到、体力、抽卡付费、跨游戏战斗数值或开放聊天。用户允许全部项目通过 AI 新建或替换美术，旧素材仅为可选参考。先验证视觉样本与游戏循环，再分批生成；占位素材与最终素材明确标记。美术生成授权不自动扩展为音乐生成、声音克隆、新付费采购或生产部署。

任何游戏没有完整开始—游玩—结算链路时，不能以漂亮菜单作为任务完成依据。没有双浏览器通信证据，不声称多人完成；没有真实断网验证，不声称离线完成；没有设备实测，不声称音游延迟达标。
