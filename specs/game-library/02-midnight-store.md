# G2《下播后的便利店》计划书

## 最新用户调整（2026-10-11）

本轮用户要求便利店只保留岁己与栞栞，移除灰泽满。此要求优先于下文原始“三名顾客”范围；保持七夜、二十一时段与三种店铺结尾，第三时段改为两人的共同街区故事。两位顾客使用该游戏专属 AI 日常装立绘。当前正在调整，未验收状态见 [开发交接](implementation/HANDOFF-2026-10-11-G2.md)。

## 定位

单人轻经营与人物故事，七个夜晚构成完整章节，每夜目标 5–8 分钟。玩家照顾一家架空夜间便利店，通过备货、推荐和倾听影响来访者后续故事。无联网要求，无反应速度惩罚。

## 核心循环与规则

开店前备货 → 三个到访时段 → 推荐商品/选择回应 → 收款与短故事 → 闭店记录 → 下一夜。

- 首版 3 名主要顾客、9 种商品。商品有温度、口味、提神程度三个标签，顾客通过台词透露需要。
- 每晚三个库存槽，每槽最多四份；默认 50 资金。补货价格和售价固定显示，卖出利润为售价减进价。
- 需求只由已经展示的台词和章节事实决定，不设置无提示的隐藏正确答案。推荐预览显示商品标签，选择后说明顾客反应。
- 商品不合适仍推动剧情，得到不同回应，不能因为缺货错失全部内容。柜台始终可提供免费热水与倾听选项。
- 夜末按商品类型处理：包装食品留存，鲜食过夜作废且提前标注。零资金时获得一次明确说明的基础补货救济，不要求反复刷钱恢复。
- 每位顾客用三个故事标记记录“倾听/记住偏好/兑现约定”，不显示“真实好感数值”。分支来自具体行为，章节总结回顾影响。
- 第七夜按标记组合给出 3 个店铺结尾；各角色同时有一段自己的收束文本，不要求全员完美才算通关。

所有角色互动为架空故事，不模拟真实私人关系。内容要体现个性，但避免单纯堆网络梗、刻板标签或把用户推向付费亲密度。

## 内容制作边界

首版 21 个到访时段，每时段一个短场景、至多两次选择；其中 9 个关键场景承担角色线，其余负责反馈和店铺日常。每场景记录进入条件、已知线索、选项效果、后续标记与兜底台词。

先完成“第一夜＋一个后续回访”的纵向样板，再扩七夜。文字长度按手机阅读体验调整，不先生成大量无法触发的对话。素材需求：一张店内背景、三名顾客现有立绘、九个商品图标、三类纪念物。

## 页面、存档与可访问性

备货页 → 柜台场景 → 商品/回应选择 → 夜末账本 → 故事相册。可回看本夜对话、调整字号、跳过已读文本；无自动消失选项。

保存于备货确认、顾客完成和夜末；需要保存当前对话节点与已执行选择 ID，读档不重复收款或再次改变剧情标记。允许从已完成夜晚以独立回看模式体验，回看不重复奖励、不修改主档。

## MVP 与扩展

MVP 为七夜、三顾客、九商品、三店铺结尾、一个纪念相册。后续增加雨夜/庆典章节、店内装饰和角色交叉来访。

首版不做自由走动、制作料理小游戏、现实等待、多人店铺、无限 AI 对话或 50 人全量故事。

## 技术、任务与验收

独占目录 `games/midnight-store/`。叙事图与库存账本分离；对话 effect 使用有限动作白名单，不执行内容字符串中的代码。

任务 G2-01 至 G2-04：首夜回访切片 → 七夜分支 → 存档相册 → 文案与浏览器验证。

- 自动检查所有节点引用、可达终点、标记前置与商品 ID；每个非结尾节点至少一条有效出口。
- 缺货、零资金、连续推荐不合适商品仍可完成七夜；库存和收入只结算一次。
- 用三条固定选择路线到达三个店铺结尾；每个顾客关键标记至少验证一次生效与未生效反馈。
- 390px 宽屏可读可选，无必须悬停才知道的商品标签；未读文本不被一键跳过误触吞掉。

风险：经营压过叙事时降低备货复杂度；故事缺少角色差异时重写三个代表场景，不用增加字数补救。
