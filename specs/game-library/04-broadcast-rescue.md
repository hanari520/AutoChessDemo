# G4《直播事故处理中心》计划书

## 定位

双人在线合作解谜，一名操作员看设备现场，一名导播看手册。两人通过文字以外的既有交流渠道或当面交流协作；游戏不采集语音。首版需两人，另提供单人阅读规则演示，但不把演示称为完整单人关。

目标体验：“我描述的红灯在他手册里有另一种含义，我们终于对上了。”教学约 3 分钟，正式关目标 8 分钟。

## 五类故障

| 故障 | 操作员看到 | 导播掌握 | 合法解法 |
|---|---|---|---|
| 麦克风路由 | 接口符号、线缆状态 | 符号对应连接顺序 | 按映射连接，不以颜色为唯一线索 |
| 模型翻转 | 模型姿态、三个旋钮 | 旋钮作用与指定目标 | 有限次变换到目标姿态 |
| 场景切换 | 四张场景卡与提示灯 | 节目顺序与禁用条件 | 选满足条件的场景 |
| 音画同步 | 两组离散节拍标记 | 设备型号补偿表 | 选择整数偏移，不考真实音频延迟 |
| 安全上电 | 指示灯组合、设备 ID | 根据组合查得的按钮序列 | 输入序列恢复电源 |

题目采用有限模板和种子生成，生成时同时计算唯一解或允许解集合，再用独立校验器验证。不同设备不形成循环依赖；首版最多两个故障同时激活。手册使用图文查表，禁止纯色区分。

## 正式局规则

八分钟内修好五个故障。误操作只加 15 秒罚时并反馈“条件不满足”，不会永久炸毁房间。有效剩余时间由服务器时钟和罚时计算，浏览器切后台不暂停。

可以主动申请提示：两人确认后透露当前故障的一层线索并记录使用次数；提示不阻止通关。结算区分完成时间、误操作数、提示数，不用只有零失误才能获取的强度奖励。

教学只包含麦克风路由，无计时失败，双方各有一次明确的信息交换步骤。正式局可交换角色后用新种子再玩。

## 信息与网络边界

- 服务端保存完整题目和答案，每个席位只收到自己可见数据。不能把完整答案发到浏览器后用 CSS 隐藏。
- 创建/加入 → 选角色 → 双方就绪 → 教学或正式局 → 结算 → 再开。
- 首版任一玩家断线自动进入暂停状态，最多保留 60 秒，每局最多两次；超出后友好结束且不记失败战绩。服务端控制暂停预算，不能靠反复掉线无限延时。
- 每次动作包含 actionId 与预期 revision。过期动作返回最新视图，已成功动作重复请求返回原结果。
- 房间服务重启采用 P08 的明确失效策略；UI 可重新创建房间，禁止无限重试遮住错误。

## 首版内容与排除项

1 个控制室背景、5 套设备组件、每类至少 4 个参数变体、教学关、正式关、角色互换、3 类纪念物。动画以设备反馈和舞台恢复为主。

后续扩展第三个台前主持角色、连续事故战役、玩家自定义设备组合。首版不做语音识别、自由输入答案、AI 动态谜题、实时 3D 舞台。

## 技术、任务与验收

客户端目录 `games/broadcast-rescue/`，服务端游戏规则目录 `services/game-library/games/broadcast-rescue/`。P07/P08 先完成服务合同，G4 的本地题目生成与设备 UI 可提前制作。

G4-01 生成器与解校验 → G4-02 双浏览器教学 → G4-03 正式五故障与重连 → G4-04 表现、信息隔离和试玩。

- 至少 100 个种子通过解校验与可完成性验证，坏模板启动时拒绝而非发给玩家。
- 两个浏览器只用各自可见信息完成教学；网络消息检查确认无对方手册/答案泄露。
- 同时点按钮、重复请求、错序、断线计时与重连均保持一致状态；暂停次数耗尽处理明确。
- 390px 手机可查表并操作，不要求另一方看到自己屏幕；相似符号必须有可朗读名称。

若两人不用交流就能完成，减少界面泄露的提示；若必须猜手册未记载的规则，则补足线索而不是让玩家多试。
