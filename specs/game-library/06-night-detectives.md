# G6《星夜调查社》计划书

## 定位

单人短篇调查游戏。三名虚拟主播组成架空调查小组，通过场景观察、访谈和证据关联解决直播世界的小谜案。首案目标 20–35 分钟，无联网、无倒计时、无操作速度门槛。

首案工作名《消失的返场节目》：联合演出前，返场清单被替换，舞台系统留下互相矛盾的记录。寻找真实操作顺序和动机；故事不涉及现实主播指控。

## 内容范围

四个场景：控制室、排练室、后台走廊、道具间；三名可询问人物；十二条证据；三个需要提交的推理命题；两种收束方式，案件事实一致，最终处理选择不同。

证据设计先写“实际时间线”，再写角色各自知道什么、为何误解、玩家在哪里能发现。每条关键推论至少有两条可获得证据支撑，不靠冷门主播知识或像素级寻找。

## 核心规则

- 点击热点调查，证据加入手册；已发现热点改变状态，提供可开启的热点提示。
- 对话解锁根据证据 ID 判断。所有必要证据在提交最终推理前都可回访，不因一句选错而永久丢失。
- 三个命题分别要求选择“事件/人物/顺序”及两条支撑证据。例如“清单是在何时替换”，不接受任意无关证据堆满。
- 错误推理说明哪一类矛盾未解释，保留已经正确的部分；无生命惩罚、不清空证据。
- 提示分三层：关注场景 → 关注证据 → 推理解释。使用提示标记在结算中，不阻止结尾或基础纪念物。
- 完成事实推理后选择处理方式，得到两种情绪不同的结尾。不能用最后一个无提示按钮突然改写事实。

三名主角的不同观察台词用于风格，不把必需线索锁在必须事先选择的角色后面。

## 页面与存档

章节选择 → 场景 → 对话/热点 → 证据手册 → 推理板 → 结尾。证据支持并排比较，手机提供切换卡片与固定命题栏。

每获得证据、完成对话或提交命题后自动保存；记录节点与已执行效果，恢复不重复奖励。结尾后支持章节回看和新槽重开，主档与回看分开。

## 素材与制作方法

先用线框场景和文本完成案件图，确认可解后制作四张场景图、十二个证据图、角色立绘和结尾插画。热点使用独立布局数据，不将文字线索仅烘焙进图片。

首版不做自由行走、配音全覆盖、开放世界、随机凶手、无限 AI 剧情。后续每案以内容包增加，可复用证据和推理组件，不重复改引擎。

## 技术与任务

目录 `games/night-detectives/`；case.json 定义节点、证据、命题、效果和提示。数据只允许预定义操作。建立案件校验工具，验证 ID、引用、前置、可达结尾和线索依赖环。

G6-01 案件事实图与可玩样板 → G6-02 完整四场景 → G6-03 保存/提示/回看 → G6-04 文案线索与浏览器验证。

## 验收

- 从新档沿不使用提示的证据路径到达两个结尾；再测试先访问任意场景、错误推理多次、先读证据后对话，均不软锁。
- 每条推论能指向游戏内已展示的证据；不存在仅策划文档知道的关键事实。
- 引用校验与路径遍历通过；提示只揭露当前命题的信息，不提前泄露未进入章节。
- 真人试玩记录卡住的位置、所见线索与错误推理原因。至少一次让未读答案的人试玩后才能声称“案件可理解”。

主要风险是作者视角过强：遇到多人在同一步卡住，补足证据关系或反馈，而不是把标准答案藏得更深。
