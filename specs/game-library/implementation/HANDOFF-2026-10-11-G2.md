最新规则约定：

- 七夜，每夜三个时段，仍为 21 次到访。
- 顾客只有 `suiji`、`kanban`。每夜 slot 0 是岁己、slot 1 是栞栞；slot 2 是共同街区/店铺故事，由岁己在奇数夜、栞栞在偶数夜领衔。
- 原灰泽满七个场景已由规则代理重写为两人的共同故事，而非只替换姓名；需要最终核对引用与可达性。
- 库存上限是 **三个不同商品 ID，每种最多四份**，不是“热柜/冷柜/货架各四份”。`storage` 商品字段只作保存类别标签。
- 包装商品跨夜保留，鲜食闭店作废；免费热水与倾听始终能推进；零资金只有一次明确救济。
- 每位顾客三个布尔故事标记：`listen`、`preference`、`promise`；不显示好感数字。

核心 API：

```js
createGame({seed, runId})
reduceGame(state, {type, actionId, ...fields})
validateState(state) // boolean
getScene(state)
previewRecommendation(state, productId)
getEnding(state)
createReplay(state, night)
```

阶段：`stock → recommend → reply → receipt → night-end → stock/complete`。
动作：`buy/return {productId, quantity}`、`open`、`recommend {productId|'water'}`、`reply {replyId}`、`advance`、`next-night`。
另导出 `STOCK_CAPACITY`、`STOCK_TYPE_CAPACITY`；内容导出 `PRODUCTS`、`CUSTOMERS`、`SCENES`、`ENDINGS`、`TAG_LABELS`。

UI 已尝试实现：每次动作自动保存、CAS revision 冲突保护、损坏/未来版本导出与显式导入恢复、不可用存储的内存试玩导出、字号偏好、已读折叠、相册、独立夜晚重放、完成奖励和新局确认。**这些是代码实现范围，最终版本尚未完成浏览器验收。**
