## 已有实现

### G1 规则和内容

文件：`games/studio-manager/core.mjs`、`content.mjs`、`core.test.mjs`。

- 六名成员、五节目、十二个固定种子无放回事件、四周每周三档、三类设备各两级升级、三终演评价。
- 初始资金 100、成员精力 80；未出场恢复 15；免费休息全员恢复 25。
- Q、节目经济与精力均由纯规则核计算，UI 不另算；事件明确成本和效果。
- `createGame({seed,memberIds})`、`previewShow(state,programId,memberIds)`、`reduceGame(state,action)`、`validateState(state)`。
- 动作：`show/event/rest/upgrade/advance/finale`，每次必须携带 actionId，重复动作幂等。
- phase：`planning → event → result → planning`；第十二档后 `finale → complete`。
- 终演允许选择任意三种不同的已配置节目，不要求之前全部播过，避免全休息/单节目路线软锁。
- 验证器已加固当前节目、事件、history、result、finale、精力/原因/Q 数据及引用；不会通过重新计算数值来验证成绩真实性。
- 三路线模拟：专精路线 50 分 `steady-debut`；均衡轮换 82 分 `spotlight`；休息恢复路线 49 分 `steady-debut`。全休息到 `first-steps`。数值尚未经过真人平衡验证。

### G1 界面

文件：`games/studio-manager/index.html`、`app.mjs`、`style.css`。

- 选三成员新建、排节目、选出场成员、预览、事件、单档/周结算、终演与再次经营链路。
- 手机有档期/成员/设备页签；确认开播和免费休息已调整为手机底部固定操作条。
- 自动保存、刷新恢复、JSON 导出导入、存储失败提示及内存档案导出、音效偏好。

- 多标签页 revision 冲突时停止操作并提示刷新，不能静默覆盖。
- 坏档或未来版本档案禁用新建，允许导出原档及确认后导入有效备份；恢复要求 quarantineId 与原始记录/revision 匹配，旧档保存在隔离仓。
- 三本地纪念物：`studio-first`、`studio-diverse`、`studio-best`。没有在线可信战绩。
- 终演评分明细已由 UI 渲染 core 返回的 `components`，不是空的 `reasons` 字段。

### 共享本地基础

文件：`library/contracts.md`、`contracts.mjs`、`contracts.test.mjs`、`storage.mjs`、`storage.test.mjs`、`save-transfer.mjs`、`collectibles.mjs`、`collectibles.test.mjs`、`rewards.json`。

- 返回 `{ok:true,value}` / `{ok:false,error:{code,message,details?}}`。
- IndexedDB：`vtlib-game-library` v1；stores 为 `gameSaves`、`completions`、`collectibles`、`corruptSaves`。
- 存档键 `vtlib:<gameId>:<slotId>`；save/rules/contentVersion 当前均为字符串 `1`。
- `loadSave(gameId,slotId='main')`；`saveGame(envelope,expectedRevision,{recoveryId}?)`。新档 expectedRevision 0，写入 revision 必须为 expectedRevision+1。
- `loadSave` 遇损坏或不支持版本时保留快照，并返回 `error.details.quarantineId/currentRevision`。
- `createSaveExport(envelope)` 同步导出当前内存档；`exportSave(gameId,slotId,{storage})` 异步导出实际槽位，包括坏档恢复副本。`exportSave(envelope)` 也支持同步形式。
- `parseSaveImport` 检查包装格式和 gameId；`importSave(json,{storage,expectedGameId,expectedRevision,recoveryId?})` CAS 写入。
- `recordCompletion` 幂等；拒绝客户端自称 server 信任；奖励目录临时加载失败可重试，不永久缓存失败结果。
- 最后还请求平台代理修复实际旧角色 ID `liAn` 的大小写兼容：仅 Character / Profile 本命字段应允许稳定混合大小写，game/run/reward ID 仍保持原限制。**交接时请核实这一小改动是否已经落盘并测试，不要假定已完成。**
