## 2. 项目背景

- **产品**：单文件网页游戏《虚拟棋战》。`autochess/index.html` 约 5.7MB / 7300+ 行，HTML+CSS+JS 全内联，**无构建步骤、零新增运行时依赖**。
- **玩法**：自走棋。经典模式 = 100 回合 / 4 章（每章 25 回合，第 25/50/75/100 回合守关，**守关失败即刻终局且无重试**）。
- **目标用户**：**虚拟偶像粉丝优先，自走棋硬核玩家为辅**。取舍原则：**「让我推的角色放出技能」优先级高于「难度曲线精确」**。
- **本轮要解决的问题**（均已定量核实，详见方案文档 §1–§4）：
  - **L-1/L-2/L-3**：核心循环缺口 —— 战斗段零操作且不可归因；结算只给数值回执不给行为回执；章末决策同质化。
  - **R-1**：**奖励真空** —— 质变奖励（增强三选一）100 回合只有 3 次，**r26–r49 有 24 个回合零质变**。
  - **R-2**：**反馈只有两层** —— 缺「决策回执」与每 5 回合的「成长确认」。
  - **机制时刻表缺失** —— 教学载体够、时刻表缺；8 项机制没有教学（休息标识 / 装备配方 / 守关预告 / 升星券引导等）。
  - **指标盲区** —— **心理卡点（玩家在哪里退出）完全无数据**，需先埋点。
- **已完成的改造（勿重复做）**：见 `autochess/specs/implementation-log-2026-09-25.md`。已上线：三分钟上手引导、开局定向招募、败因归因、敌方人数边界平滑、技能可读性（一句话定位 / 大招金环 / 结算施法次数）、图鉴收集层、本命标记、分享卡、羁绊可达性修复、榜单规则版本戳。

## 4. 硬约束（违反任何一条 = 返工）

1. **禁止调整任何难度参数。** `DIFF_TUNE_BASE` / `CH_DIFF` / `CH_BOSS` / `CH_INTRA` / `enemyCap` / `ENEMY_CAP_BY_CH` / `BATTLE_HP_MUL` / `BATTLE_START_MANA` / `SKILL_STAGGER` / `XP_NEED` / 连败补贴 / 连胜加压 / 扣血公式 / 怪物掉落件数 / `SHOP_ODDS` 与全部经济数值。**一个数字都不能动。**
2. **禁止在新增代码里调用 `rand()`。** 游戏的随机数是共享序列，任何一次额外调用都会让后续敌方阵容、商店、掉落全部偏移 → 逐字节对比立刻失败。**这是本轮最容易犯的错。**
3. **收集层与内容层不得附带任何数值加成。** 新增展示数据字段名不得含 `atk/hp/maxhp/ar/mr/asp/mana/crit/dmg/lvl/cost` 等战斗字段。
4. **所有新增 UI 必须有自动分支**：`globalThis.__HEADLESS` 为真、或 `S.auto` / `S.autoFight` 为真时，**不得弹窗阻塞回合**（历史踩坑：G4 开局招募就是靠自动兑现才没破坏无头测量）。
5. **弹窗预算**：单回合新增弹窗 ≤ 1；不得破坏既有顺序（首局：三分钟上手 → 开局招募，这个顺序已有验收脚本固化）。
6. **改动前先备份**：`cp autochess/index.html autochess/index.html.bak-$(date +%Y%m%d-%H%M)`。
7. **A/B 必须同种子同口径**。`N=100/SEED=11` 与 `N=300/SEED=7` **不可相减**；跨口径只能作方向性参考并显式标注。
8. **回合判定一律用函数**：`chLen()` / `runLimit()` / `fourChapterCampaign()` / `normalCampaign()`。**不要写死 25 / 100**（诅咒 `shortch` 下 `chLen()` = 15）。
9. 若最终发现某项确实移动了通关率 → **按 nerf/buff 处理**，必须跑 `sim.js N≥300`、把漏斗写进 `CHANGELOG` 固定表，并把 `CAMPAIGN_RULES_VER` +1 且同步两个后端（`autochess-api/cloudbase-functions/lb/index.js` 与 `autochess-api/src/index.js`）。

## 5. 任务清单

> 所有行号仅供参考，**一律用 grep 定位**（行号会漂移）。

### T1 · 5 项体验埋点（优先级最高，T4/T5 依赖它）

**为什么**：方案的指标树里，**心理卡点（退出回合分布）是第一目标**，而它现在完全没有数据。不先做这项，后续所有"要不要继续投"的决策都是猜。

**做法**：新增一个统一遥测入口，禁止在战斗热路径调用。

```js
/* 遥测：统一入口。禁止在战斗 tick / 伤害结算里调用。
   无头（__HEADLESS）下只聚合到 S.stats.tele，不写 localStorage。 */
function tele(name, n=1){ (S.stats.tele = S.stats.tele || {})[name] = (S.stats.tele[name]||0) + n; }
```

要采集的 5 项：

| # | 项 | 采集点 | 采集内容 |
|---|---|---|---|
| 1 | **会话时长 + 退出回合** | `saveGame()`（约 `:7337`）与 `gameOver()` | 上次保存到本次保存的时间戳差；本局存档的 `S.round` 快照 |
| 2 | **每回合决策时长** | 进入 `prep` 与离开 `prep` | 单回合备战墙钟；**无头下跳过** |
| 3 | **精英挑战接受 / 拒绝** | `chooseChallenge()`（约 `:2149`）；以及备战期结束时未选也算一次「拒绝」 | 计数 + 当时回合 + 当时 HP |
| 4 | **增强三选一的选择分布** | `pickAug(i)`（约 `:6374`） | 选择的 `aug.id` + 稀有度 + 当时回合 |
| 5 | **生命压力回合数**（供 P1 的 DDA 通道 C 用） | 每回合末 | `S.hp <= hpMax()*0.6` 的累计回合数 |

**落盘**：统一写 `localStorage.vc_tele_v1`，结构 `{ v:1, sessions:[...], counters:{...} }`。**只在回合末与终局写**，不要每 tick 写。

**关键验收**：
- `__HEADLESS` 下不写 localStorage（`tools/sim.js` 用的是内存桩，第 57 行），但 `S.stats.tele` 有值；
- 新增 `env TELE=1 node tools/sim.js 300` 能打印聚合结果（至少含 `eliteAccept` / `eliteDecline` / `augPick.*` 分布）；
- **同种子逐字节 diff 必须为空**（见 §6.2）。

### T2 · `sim.js` 扩展「每回合死亡计数」导出

**为什么**：硬卡点的判据是「某回合死亡局数 ≥ 全局基线 2×」。现在 `sim.js` 只输出累计漏斗，看不到回合级分布。

**做法**：在 `tools/sim.js` 里统计每局终局回合（`gameOver` 时的 `S.round`），输出：
1. 100 行直方图数据（回合 → 死亡局数）
2. `卡关点 Top5`（按死亡局数降序）
3. 与基线的比值（`该回合死亡数 / 均值`），把 ≥2× 的标红

**注意**：`sim.js` 从 `index.html` 正则提取 `<script>`（非贪婪 `[\s\S]*?`，文件里有两个 script 块）—— **不要改 script 标签结构**。

**验收**：`MAXR=100 node tools/sim.js 300` 输出直方图与 Top5；N=300 噪声约 ±4pp，**不要追单点**。

## 8. 已知陷阱（每条都真实踩过）

1. **`rand()` 是共享序列。** 新增任何一次 `rand()` 调用都会让敌方阵容/商店/掉落全部偏移，逐字节对比直接失败。**本轮只做展示与信息，不需要随机数。**
2. **跨口径对比会得出错误结论。** 曾用 `N=100/SEED=11` 与 `N=300/SEED=7` 相减得出"通关率 −6.7pp"，补跑同口径后真实值是 **−4pp**。先确认口径再下结论。
3. **`#flowShell` 会拦截所有点击。** 页面初始停在 flow 首页，顶栏与弹窗都被遮罩压住。须 `showFlowPage('game')` 或真正开局后再操作。图鉴是弹窗 `#bookModal`，同样被压。
4. **整页截图可能空白但 DOM 是对的。** 用 `locator('#元素').screenshot()` 元素截图，并用**文件体积**判断有效性（真实 UI 截图 ~1MB，纯空白远小于此）。
5. **残留存档会让流程卡住。** 有 `vc_save4` 时点「新的对局」先弹放弃进度确认页，后续点击全失效。清 localStorage 要"保留引导标记、清掉存档"。
6. **热路径禁用 `isPassive()`**（内部是 50 元素线性查找）。战斗中必须用缓存标记 `u.isPassiveFlag`。战斗热路径也禁新增 `getComputedStyle`。
7. **战斗单位对象无 `job` 字段**，读职业用 `byId(u.id).job`。
