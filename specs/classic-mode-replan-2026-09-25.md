## 0. 范围与边界

## 1. 开工前的两个阻塞项

这两件不做，后面所有工作都会失去可比性。

### 1.1 经典模式的排行榜与战绩必须加规则版本戳（P0 阻塞）

**现状（已核实）**

| 项 | 每日挑战 | 普通模式 |
|---|---|---|
| 提交时带版本 | ✅ `&rules=2`（`:6985`） | ❌ 无（`:6985` 只在 `S.daily` 时拼参） |
| 客户端版本校验 | ✅ `Number(boardInfo.rules)!==2`（`:6986`） | ❌ **被 `S.daily &&` 短路，永不触发** |
| 本地战绩落版本 | ✅ `rules:'daily100'` | ❌ 只有 `rules:'campaign100'` 类别名（`:6936`），无版本号 |

**后果**：09-23 的 `DIFF_TUNE 0.66→0.72`（`:4229`）与 09-25 的 `CH_DIFF [1,1,0.84,1.10,1.52]` / `CH_BOSS [1,1,1.90,1.90,2.40]`（`:4218-4219`）已经让前后难度不同的成绩混在同一张 `normal100` 榜上直接排名。而 Step 5 会再改一次难度。

**修法**（照抄每日榜已有的成熟模式，改动量很小）

1. 在 `DIFF_TUNE` 旁定义 `const RULES_VER = 2;   // 任何影响难度的改动 +1`（`:4229` 附近）
2. 提交时 `rules:S.daily?2:RULES_VER`，并把 `&rules=` 拼进 `normal100` 的查询（`:6985`）
3. 客户端校验改成对普通榜也生效（`:6986` 去掉 `S.daily &&` 短路），失败走已有的"新版榜服务尚未更新，成绩已记录在本地排行"降级文案
4. 本地战绩写入 `rulesVer`（`:6936`），`rankedHist` 按版本过滤历史成绩展示

**为什么排在最前**：不修，Step 5 之后榜单就再也说不清"这个第 7 名是什么规则下打出来的"。

### Step 1 · IP 表达修复（"我推的大招放不出来"）

**这是唯一模式下粉丝收益最高的一步，且不依赖任何后续改动。**

| 顺序 | 项 | 位置 | 动作与参数 |
|---|---|---|---|
| 1 | **C4** 剥离 `HP_SCALE` | `:2250, 4273, 4472-4519` | 从敌方 `mul` 中移出，改为在 `makeBattleUnit` 对双方统一应用（或改名 `ENEMY_HP_MUL` 并写清作用域）。**这是 TTK 旋钮真实可用的前置** |
| 2 | **C1** 技能节流与表现队列解耦 | `:4764, 4788, 4918-4926` | ① 删掉 `readyCasters` 的全局 `t-lastCastAt>=SKILL_STAGGER` 门槛，改为每单位独立判定；② 新建 `castBannerQueue`，把技能名 cut-in 与特效按 800ms 依次播放（机制即时结算，表现延后播完）；③ 开局蓝量全员 `+25`；④ 攻击回蓝由 `min(伤害/1.25, 15/30)`（`:5025`）改为 `8 + 伤害/6`（保持上限），让低攻单位也有稳定回蓝通道 |
| 3 | **C2 局部**：沉默只封施法不封受击回蓝 | `:5022, 5155` | 只做这一条，不做完整递减系统。理由：C1 提高施法频率后，"被沉默 → 永不放技能"的伤害被放大，这一条是 C1 的必要配对 |
| 4 | **E3** 技能可读性 | `skillDesc` `:2852+`、详情面板、结算 | ① 详情面板顶部加一句话定位（从 `COMBAT_KITS[id].mode` + 状态旗标自动生成）；② 蓝满就绪的地面标记；③ 结算列出"本场施法次数" |
| 5 | **G3** 本命标记 | 详情面板 + `signatureFx` | 玩家标记 1 名本命（可换）：施法时 cut-in 升级 + 战场高亮 + 伤害数字专属色 + 结算单列一行 |

**验收**
- 单棋子每场施法中位数 **≥ 2**，0 次占比 **≤ 20%**
- TTK 落在 **8–11 秒**
- `sim.js N≥300` 四章漏斗不劣化超过 2pp

**风险**：C1 会让总伤害量接近翻倍 → TTK 缩短。**必须先做 C4 才有安全的 TTK 补偿手段。** 若 TTK 掉到 6 秒以下，用剥离后的全局 HP 倍率补回，而不是去动 `DIFF_TUNE`。

### Step 2 · 第一小时

| 项 | 位置 | 动作 |
|---|---|---|
| **E5** 三回合新手引导 | 新增；复用 `:3007` 首局欢迎指引与 `showHelp` | 回合 1 只开买牌+上阵 → 回合 2 加刷新+合成 → 回合 3 加利息+站位。每步先让玩家做完，再解释"你刚做了什么、为什么" |
| **G4** 开局自选一名角色 | 复用 `showDailyOffer()` `:1958-1981` | 开局从 1–2 费池自选 1 名进备战席。第一分钟建立情感锚点，同时降低开局决策焦虑 |
| **G6** 第 1 章难度重分配 | `:4218-4219` | `CH_DIFF` / `CH_BOSS` 重标定：ch1 条件通过率 80% → 91%，把难度预算挪到 ch3（60% → 54%）。整体通关率保持 58–62% |
| **D3-cliff** 敌方人数边界平滑 | `:2008, 4262` | 现 `enemyCap` 在 r26 从 7 阶跃到 9、r51 从 9 到 10，而玩家人口是连续缓慢增长 → **第二章开局突然多打 2 人**。改为章节边界前 5 回合线性过渡（见下方代码）|
| **E2** 败因归因 | 结算面板 `reportHTML()` `:6308+` | 用 `battleStats` 生成 1–3 条候选原因 + 1 条可执行建议。例："你的核心【XX】全程被沉默 3 次，**一次技能都没放出**" → "把它移到第 3 排" |

**D3-cliff 的具体改法**

```js
// 现：function enemyCap(r){ return !fourChapterCampaign()?7 : r>50?10 : r>25?9 : 7; }   // :2008
const CAPS = [7, 9, 10, 10];
function enemyCap(r){
  if(!fourChapterCampaign()) return 7;
  const idx = Math.min(Math.ceil(r/25), 4) - 1, cap = CAPS[idx];
  const prev = CAPS[Math.max(0, idx-1)];
  const inCh = ((r-1) % 25) + 1;
  return inCh <= 5 ? Math.round(prev + (cap-prev)*inCh/5) : cap;
}
```
效果：r26 不再从 7 跳到 9，而是 7→7→8→8→9（r26–r30）；r51 从 9 平滑到 10（r51–r55）。**不要**同时加 `min(..., S.lvl+1)` 这类按玩家等级削敌方人数的规则——它会造成"不升级就不会遇到更多敌人"的反向激励。

**验收**：ch1 条件通过率 ≥ 91%；整体 58–62%；r26 / r51 的敌方人数曲线无阶跃。

### Step 3 · 长局承载：把"40 分钟"改造成"可中断连载"

**这一步是砍掉单人模式后新增的必做项。**

砍掉巡演企划后，经典模式是**唯一入口**，而它的单局是 100 回合 ≈ 35–50 分钟，且 50% 的失败发生在第 4 章（即投入 40 分钟后白给）。粉丝向产品不能靠"缩短单局"解决——100 回合的结构一动，全部难度基线都要重画。正确解法是**让单局变成可随时中断、可续读的连载**：

| 项 | 位置 | 动作 |
|---|---|---|
| **"继续上一局"升为首页第一入口** | `renderSetup()` `:6762+`、`inspectSave()` `:6708+` | 有存档时，首页第一视觉位置就是"继续 · 第 2 章 · 第 34/100 回合"，模式选择退到次要位置 |
| **章节存档点** | `saveSnapshot()` `:6850`、`loadGame()` `:6888` | 现有存档只在备战检查点（`recoverablePhase:'prep'`）。增加章节快照：守关战后额外存一份，失败或主动放弃时可"从本章开头重开（保留阵容与金币）"。降低 40 分钟投入的心理风险，且不降低难度 |
| **进度可视化** | 顶栏 `:1036` 附近 | 常驻"第 N 章 · 第 R/100 回合"与本章剩余回合数，让"还要多久"可见 |
| **G7** 每日打卡化 | 首页卡片 | 连续参与天数 + 显示"你已连续参与 N 天"；每日挑战卡片前置。粉丝的日活驱动是陪伴感而非高难挑战 |

**验收**：单次会话时长中位 **8–15 分钟**；退出后重新进入的转化率（需埋点）。

**明确不做**：不缩短回合数。若后续仍需要短局，应作为**新模式**添加（2 章 50 回合、难度曲线按比例压缩），而不是改造现有 100 回合基线。

### Step 5 · 数值重构（成组改、成组测，只做一次）

**这一组必须一起上线再一起测**，单独改任何一项都会失真。

| 项 | 位置 | 动作 |
|---|---|---|
| **A1** 羁绊门槛重标定 | `FACTIONS`/`CLASSES` `:1401-1429` | **12/22 个羁绊的顶档要求"该阵营/职业全员到齐"**，而自然经验封顶 9 级 → 森之国 T2 需 6 人 = 67–75% 人口。按 `最高档 ≤ min(成员数×0.67, 人口×0.5)` 重解门槛；补齐薄阵营（星际/学园/花语/偶像各只有 3 人） |

| **C3** 护甲软上限 + 破甲改比例 | `:5119-5124, 1462` | 现 23 护甲 = 59.7% 减伤、37 = 71.9%，且破甲把低甲目标打成负值反向暴增伤。① 30 点以上每点减伤系数 ×0.5；② 破甲由"−20 点"改为"−25% 当前护甲（下限 −4）」；③ 法师 T2 的 −72% 魔抗同源，改为比例削减 + 负抗性下限 −50% |
| **D2** 战斗内随机去噪 | `:4937, 4957` 等 | 暴击改"每第 N 次必暴"、闪避改 Pity。保留受击回蓝浮动。理由：TTK 6–8 秒时，几次随机就能翻转胜负，玩家的因果归因会崩 |

**验收**：四章漏斗 **91 / 70 / 54 / 45**，整体 **58–62%**；三组对抗场景胜率极差 ≤ 12pp（全守护 vs 全物理 / 全法师 vs 全守护）；`goldIdleRatio < 25%`。
