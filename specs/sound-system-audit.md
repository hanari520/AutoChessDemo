# 声音系统重设计与验收

## 声画事件约定

| 事件 | 声音落点 | 验收场景 |
| --- | --- | --- |
| 购买、刷新、出售、装备 | 操作成功并产生对应界面变化时 | 失败操作静默；购买触发升星时先购买后升星 |
| 布阵、升星、等级提升 | 棋子或数值变化的视觉反馈出现时 | 一次成功动作只触发一个对应提示，组合动作顺序清晰 |
| 开战、羁绊、野怪 | 战斗图层与羁绊效果出现时 | 普通与野怪回合可区分，羁绊不盖过开战声 |
| 技能蓄力 | 蓄力环开始时使用轻起手提示 | 单体、群体、治疗、护盾、控制均有正确音色 |
| 技能命中 | 弹道抵达或主特效最亮时播放主体声 | 多目标技能只播一次群体主体声，避免叠音 |
| 持续区域 | 区域生成时播放一次 | 不随每次伤害 tick 重播 |
| 暴击、闪避、死亡 | 对应受击/闪避/消失动画处 | 密集战斗中重点声音保留，同帧死亡不齐响 |
| 回合/章节结果 | 横幅或结算内容出现时 | 胜负、最终通关、回合收益提示层级清楚，无重复压音 |

## 原实现问题记录

- `castSkill` 与 `castV3Skill` 均在蓄力起手时播放完整技能声，早于弹道、落点与群体效果主画面。
- `castV3Skill` 只按少数 `mode` 和 `attackStyle` 选音，护盾可能成为斩击，火、冰、雷等可能成为暗系。
- 声音合成使用游戏 `rand()`，会推进每日挑战的战斗随机数状态。
- 并发上限把同一音效的每个音符单独计算，琶音可占满容量；调试发声计数在限流和容量检查前增加。
- 声音时长固定，而部分战斗动画依据 `--spd` 缩放；购买触发升星时现有调用顺序也与视觉语义相反。

## 核验原则

声音必须为纯表现层：静音、无 `AudioContext`、页面后台与不同播放速度均不改变战斗数值、随机数状态、存档或事件顺序。实际发声计数只统计通过限流并安排播放的事件。静音偏好跨重载保持。浏览器与无头模拟均不得抛错。

## 本轮落地

- 技能分为蓄力环出现时的轻提示和主体声；由于当前技能伤害与主体 VFX 在同一帧出现，主体声按效果于 `0–70 / SPEED` 毫秒内进入。每次施法只安排一次主体声，群体技能不会按目标人数叠放。
- V3 技能按护盾、治疗、冻结、控制、斩击、水、毒、暗系及弧光选音；持续区域在生成时播放一次。旧技能原型保留火、冰、电、暗、治疗、护盾等专用音色。
- 成功购买先播放购买声，若升星则约 90 毫秒后播放升星音；普通开战与野怪号角互斥；胜负横幅先响，最终通关页另有通关音。
- 一次合成音效占一个并发名额，优先级允许胜负等关键提示替换低优先级战斗声。声音噪声使用独立序列，不消耗游戏随机数。

## 自动与浏览器验收

- `node tools/sound-system.test.js`：10 组通过，覆盖 RNG 隔离、并发回收与优先级抢占、限流后的计数、静音与无音频环境、真实 V3 技能映射、终结技能音保留和系统音接线。
- `SEED=42 MAXR=5 node tools/sim.js 1`：五回合无头战斗执行完成。
- Chromium 浏览器：页面交互与实际 `AudioContext` 播放后没有页面异常；购买和普通开战均计入实际发声次数。
