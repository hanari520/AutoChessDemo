# 星域棋战 · VirtuaReal 自走棋 Demo

虚拟偶像主题自走棋（VirtuaReal + P-SP 角色阵容），包含经典闯关、每日挑战、自定义诅咒与「星域小队」异步竞技场。游戏规则与战斗仍由 `index.html` 驱动；界面皮肤、舞台演出和施法表现拆分在 `tools/idol-ui.css`、`tools/idol-redesign.css`、`tools/idol-ui.js` 与 `tools/idol-ui-redesign.js`，无需构建或安装依赖。

## 本地游玩

动物自走棋式原型「星域小队」已提供独立入口 `arena.html`，也可从主页或新建对局页面直接进入。支持五人队列、50 个原版棋子、50 种技能机制（新增衣装立绘暂存，未启用）、十金商店、合并升级、培养道具、单项冻结、技能事件回放与十胜五命。

线上竞技场已连接 CloudBase HTTP 云函数，个人对局、请求幂等记录与阵容库均存储于私有 PostgreSQL 表。本地异步试玩：运行 `node arena/server.mjs`，打开 `http://127.0.0.1:8082/arena.html`。服务保存个人对局与其他玩家提交的阵容，不要求对手同时在线。CloudBase 阵容库配置及验证见 [arena/README.md](arena/README.md)。主页和新建对局中的剧情模式入口已由异步竞技场替换；旧剧情代码和存档保留。

直接用浏览器打开 `index.html`，或：

```bash
python -m http.server 8081 --bind 127.0.0.1
# 访问 http://127.0.0.1:8081
```

## 部署（Cloudflare Worker）

线上 `autochess.hanari520.cn` 由 Cloudflare Worker `autochessdemo`（纯静态资源托管）提供，配置在根目录 `wrangler.toml`。**推送 `main` 后由 Cloudflare Workers Builds 自动构建上线（几分钟内生效），无需手动部署**；如需手动兜底：

```bash
npx wrangler deploy   # 把本目录作为 Worker 静态资源上传；排除项见 .assetsignore（out/ 工作产物、assets/units_redraw 源图、assets/campaign 离线战役美术、tools/_* 开发脚本等）
```

自定义域 `autochess.hanari520.cn` 已在 Cloudflare 侧绑定该 Worker。入口即根目录 `index.html`（含 PWA manifest 与 Service Worker），无需任何构建步骤。

## 模式结构

「新建对局」提供 🎲 普通模式、📅 每日挑战、⚠ 自定义诅咒三张模式卡；原剧情模式卡位已替换为「✦ 星域小队 · 异步竞技场」，点击直接进入菜单、卡组与队名选择、商店准备、战斗和结果流程。主页也提供快捷入口。

其余四种独立玩法（首领狩猎、战术解题、守城生存、战役征服）与旧版八人竞技入口**已暂时下线**（2026-09-26 批次 D/E 决定）：玩法定义与代码保留在 `tools/solo-modes.js` 等文件中，可随时恢复；旧八人竞技引擎与旧存档同样保留。首页另有「八人联机 · 好友房间」入口；它使用独立房间服务和确定性战斗模拟器，技能已逐棋审计。与单人规则的设计差异见 [技能审计报告](specs/online-skills-audit-2026-09-29.md)。

存档槽位：经典普通写 `vc_save4`，每日挑战写 `vc_daily3`，八人竞技写 `vc_arena3`，四种单人玩法各写 `vc_solo_v1_<mode>`。模式状态与备战棋盘在安全检查点自动保存，战斗中打开菜单会暂停单人战斗时钟。新模式的成绩当前只保留在本地存档，不进入经典排行榜。

## 八人联机

联机服务运行在腾讯 CloudBase 云托管（上海）的单实例 Node 容器，地址为 `https://autochess-online-321604-12-1450980602.sh.run.tcloudbase.com`。打开 `https://autochess.hanari520.cn/online.html` 可创建房间；房主可添加机器人补满八席。服务端运行说明、房间协议和测试入口见 [server-online/README.md](server-online/README.md)。

本地联调时，仓库根目录运行 `python -m http.server 8081 --bind 127.0.0.1`，`server-online/` 中运行 `npm install` 和 `npm run dev`，再打开 `http://127.0.0.1:8081/online.html`，在高级设置中将联机服务地址改为 `http://localhost:3000`。云端容器须单独部署，推送静态页面不会更新容器。

当前八人房间支持邀请码、八席大厅、房主添加/移除机器人、就绪开局、共享卡池、商店、布阵、确定性战斗事件回放、经济回合、淘汰、名次和断线重连。房间状态与战果由服务端负责，所有玩家看到同一份战斗结果。房间仅存于单个容器实例内，服务重启会清空正在进行的对局。

对局界面与经典模式完全一致（2026-10-01 起）：`online.html` 直接复用 `index.html` 的操作界面骨架、渲染结构与皮肤（核心样式副本 `online/classic-ui.css` + 同一批 `tools/` 样式），操作手感（拖拽、点选、快捷键、出售、装备、触屏抽屉）与经典一致；唯一新增是右侧「八人战况」面板（8 名玩家血量与名次，点击可观战其他玩家棋盘）。

开发验收命令：

```bash
node --test tools/solo-modes.test.js
python tools/solo_browser_test.py
python tools/solo-puzzle-proof.py
# 八人联机（需静态 :8081 + 联机 API :3000）

```

设计与覆盖范围见 `specs/solo-acceptance.md`。

## 玩法速览

- 普通闯关模式固定 100 回合，共四章；第 25/50/75 回合击败首领后选择一项全局增强，第 100 回合击败最终首领即通关。任一守关战失败即结束本局
- 每 5 回合为野怪回合（胜利掉装备，普通野怪战失败不扣血）；普通模式第 50 回合守关胜利获得升星券，每局最多拥有一枚 4★ 棋子
- 普通模式每逢第 10 回合的非守关野怪战可主动选择精英挑战：敌方攻血 +25%，胜利多得 2 件装备和 3 金，失败失去 3 生命
- 普通模式第四章第 82、92 回合有 2★ 精英棋子带队，备战期会显示提示
- 每日挑战与自定义诅咒共用 v3 的 12 条规则：每日按日期固定一条且近 10 天不重复，自定义只能单选一条。两种模式均为四章 100 回合；每日成绩进入按日期和规则版本隔离的每日榜，自定义诅咒局不计入排行榜。详见 [诅咒规则](specs/daily-curses-redesign.md)。
- 八人竞技（入口已下线，引擎与旧存档保留）：1 名玩家与 7 名风格各异的 bot 共用卡池，每回合 1 对 1，生命归零淘汰，最后存活者获胜；玩家对局使用完整战斗演算，bot 之间用阵容战力模型快速结算；玩家出局后赛事会继续模拟到冠军产生。首页存档列表可继续已有竞技对局，无法开新局
- 经济：开局 5 金（诅咒补偿在 5 金基数上叠加）；基础收入第 2/3/4 回合为 2/3/4 金，第 5 回合起固定 5 金（`min(回合+1,5)`，回合末发放）；利息每 10 金 +1（上限 3）；胜利奖金 2 金；连胜/连败 3/5/7 → +2/3/4
- 等级=人口（开局 2 级，最高 11）；买经验 5 金 +4 经验，每回合自然 +2
- 商店 5 卡槽独立按等级概率表抽取，共享卡池 50/40/30/20/10 张
- 战斗：全棋子统一 50 蓝，开局双方各 +15 蓝（`BATTLE_START_MANA`）；攻击回蓝 = 固定基数 8 + 伤害÷6（法师/咒术/医者单次上限 30，其余 15），受击回蓝为所受伤害的 20%~40%（单次封顶 15~30）；护甲线性边际递减、魔抗百分比乘算、任意伤害 5% 保底；全场技能至少错峰 800ms、同一方技能至少错峰 1200ms 释放
- 50 枚棋子各有专属技能（破甲/减抗/变形/石化/纯粹伤害/斩杀/烧蓝/沉默等克制体系）
- 战斗系统：50 枚棋子逐个配置技能机制；普攻分刃光、箭矢、棱晶弹、节拍脉冲、碎星爆点 5 种表现，并按角色触发流血、减速、回蓝、溅射等效果。技能清单见 `assets/skill_signature_manifest.json`。
- 羁绊徽章：12 个阵营与 10 个职业使用统一重绘的 AI 透明图集，应用于羁绊栏、棋子卡片、战场徽章和图鉴；Service Worker 预缓存图集（当前 CACHE `vcache-v78`）。
- 羁绊机制：新对局的 22 项羁绊改为战斗事件效果，包含集火、施法配合、站位援护、反制和救援；旧备战存档继续沿用创建时的旧羁绊规则。人数门槛保持原样，商店刷新规则不变。

## 开发工具（tools/）

- `sim.js`：无头模拟器（Node），统计通关率/战斗时长/野怪胜率：`node tools/sim.js 300`
- `bot_strategy.js`：托管与竞技 bot 共用的自适应运营策略，按经济、血量、近期失血、战力差、对子进度、羁绊和对手阵容调整买牌、升级、搜牌、装备与站位；普通模式托管还会使用升星券并评估精英挑战风险
- `accept25.py`：浏览器连打 25 局验收：`python tools/accept25.py`
- `duoduo_doc.txt`：数值设计参考文档提取版
