# 八人联机模式实施计划

## 目标与范围

在现有《星域棋战》旁新增独立的八名真人联机自走棋模式。现有普通、每日、诅咒、巡演模式及其本地存档和排行榜保持原规则。首版以房间码邀请、八人到齐开局为默认方案；自动匹配、段位、付费和社交系统不纳入首版。

**交付分界：**先完成八席房间、共享卡池、服务端操作和简化战斗的可玩联机原型；它不等于现有单机战斗的联机版。随后迁移完整战斗演算（50 个专属技能、装备、羁绊和真实站位），经过单机镜像对照验证后才称为正式八人联机模式。

## 现状与关键决定

- `index.html` 中的旧竞技模式是本地一人对七名 bot，共享卡池、轮次配对和淘汰名次已有雏形，但逻辑依赖全局状态 `S`、`ARENA`、浏览器计时与 `Math.random()`。它是规则参考和回归样本，不是可直接联网的服务端引擎。
- 现有 `autochess/wrangler.toml` 只托管静态文件；`autochess-api` 主要提供排行榜。新增独立联机 Worker，按房间 ID 映射一个 Durable Object，避免把实时状态混入现有排行榜服务。
- 客户端仅发送操作意图；服务端验证金币、卡池、回合阶段、棋盘、装备和战斗结果。按席位发送可见信息，其他玩家商店和未公开站位不外泄。
- 联机规则使用明确版本号、单一可注入随机源、可序列化状态与操作日志。战斗服务端结算并广播结果与可回放事件；客户端只播放动画。先确定战斗性能预算，再选逐 tick 结算或压缩的事件结算。
- 首版不使用 Higgsfield 的新游戏模板迁移现有代码；参考其 `validateAction`、`applyAction`、`viewFor` 分层。Cloudflare 官方 Durable Objects 文档是实际部署方案依据。

## 产品默认规则（实现前冻结）

- 八名真人同场；房主创建房间码，八人准备后开局。掉线保留席位，允许凭恢复令牌重连；离线时使用保守托管，超时仍未回来则按已公布规则继续结算。
- 保留当前竞技的共享有限卡池、每轮一对一、生命归零淘汰、最终名次。重新审定准备时间、基础经济、野怪/装备节奏、轮空配对及单局时长后冻结为 `onlineRulesVersion`；不直接照搬经典 100 回合的节奏。
- 每轮分为备战、锁定、结算、展示四段。阶段截止由服务端时钟决定。迟到操作被明确拒绝；重复操作通过操作 ID 幂等处理。
- 排行与段位暂不接入现有单机榜；先提供房间结果和局内记录。公开匹配与奖励在首版体验验证后单独设计。

## 依赖与实施顺序

1. **冻结规则与协议**：写出八人赛的阶段、时间、卡池、配对、淘汰、掉线和可见信息表；确定首版时长目标与版本策略。验收：给定同一房间状态，任何操作都有唯一的合法/非法判断及明确错误。
2. **拆出可重放的规则核心**：从旧竞技和战斗逻辑抽出共享卡池、经济、购买、布阵、配对、战斗结算所需的纯规则；注入种子随机源。验收：固定种子和操作序列重复运行得到同一状态摘要，现有单机回归测试仍通过。
3. **两席联机纵向原型**：建立房间、两名玩家连接、购买同一卡池棋子、锁定、服务端结算一场战斗、双方看到相同结果。验收：两浏览器和自动化 WebSocket 测试均通过；非法购买、重发和越阶段操作被拒绝。
4. **扩到八席和原型赛程**：八人准备、无重复配对优先、奇数存活时的镜像/轮空规则、淘汰、卡池返还、最终排名。验收：八个独立客户端可完成全局，所有席位的经济、卡池和名次一致；页面明确标注简化战斗原型。
5. **持久化与恢复**：阶段边界持久化快照及操作序列；掉线重连按席位补发允许查看的状态；部署或对象重启后恢复计时。验收：备战和结算阶段各模拟断线/重启，最终状态与无故障对局一致且不重复结算。
6. **联机界面**：独立入口、房间大厅、准备状态、倒计时、操作失败反馈、其他玩家战况、观战和赛果。验收：桌面与手机均能完成创建、加入、对局、重连和观战；单机入口与存档不受影响。
7. **压力与公平性验收**：八人长局、并发抢购、临界时间操作、网络抖动、掉线、重复消息、恶意输入和版本不一致。验收：无负金币/超卖/重复奖励/隐私泄露；日志可按对局 ID 和操作序号复盘故障。
8. **完整战斗迁移**：把单机战斗的纯状态转换、固定 tick、50 技能、装备与羁绊效果分离出页面代码，并以固定随机源和时钟在服务端运行；用现有战斗引擎的同种子镜像用例逐项比较事件、伤害、胜负。验收：同一输入得到同一战斗日志，核心机制对照一致，八人并发战斗符合 Worker 资源预算。
9. **灰度上线**：先邀请制测试，再考虑开放匹配。联机榜独立起步，按真人数据决定经济与时长调整。验收：灰度期间可通过开关关闭联机入口而不影响单机。

## 风险与处理

| 风险 | 处理 |
| --- | --- |
| 现有逻辑与 DOM、全局变量耦合 | 先做两席纵向原型，按规则边界抽取；不整份复制到 Worker。 |
| 原型战力结算与现有自动战斗规则不同 | 清晰标注原型；完整战斗迁移和镜像对照通过前不称正式联机版。 |
| 随机与浏览器计时导致不同步 | 服务端唯一随机源、固定规则版本和服务器截止时间；保存种子与操作序列。 |
| 同局八场战斗的结算负载 | 原型阶段测单轮 CPU、内存和延迟；必要时减少广播频率、压缩事件，保留权威结算。 |
| 旧规则变动破坏正在进行的房间 | 每局固定 `onlineRulesVersion`；新版本只用于新房间。 |
| 现有榜单采用信任提交 | 联机赛果只由权威房间写入独立记录；不复用客户端提交的单机分数接口。 |

## 尚需定稿的产品选择

1. 首版是否只开放好友房间（推荐），以及是否允许未满八人以 bot 补位。
2. 目标单局时长和备战倒计时；需用真人测试后定值。
3. 掉线托管、超时退赛、观战时可见信息的具体规则。
4. 首版是否沿用当前竞技的棋子、羁绊和装备数值；推荐先沿用并为联机赛独立版本化。
